## ЧАСТЬ 2: Матрица инструментов защиты по типам данных

### 2.1 Инструменты шифрования (Encryption)

#### At-Rest (покоящихся данных)

| Уровень данных | Алгоритм | Управление ключами | Размер ключа | Режим шифрования | Реализация |
|---|---|---|---|---|---|
| **PUBLIC** | — | — | — | — | Нет шифрования |
| **INTERNAL** | **AES-256** | HashiCorp Vault (rotated every 90 days) | 256-bit | GCM (Galois/Counter Mode) | PostgreSQL pgcrypto + application layer |
| **CONFIDENTIAL** | **AES-256** | Vault (rotated every 30 days) | 256-bit | GCM | Database-level encryption |
| **RESTRICTED** | **AES-256 (field-level)** | Vault (rotated every 14 days for sensitive fields) | 256-bit | GCM | Field-level encryption in application |

#### In-Transit (передаваемых данных)

| Уровень данных | Протокол | Версия | Cipher Suite | Аутентификация | Реализация |
|---|---|---|---|---|---|
| **PUBLIC** | HTTPS | TLS 1.2 | TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256 | Certificate | Standard web |
| **INTERNAL** | HTTPS | TLS 1.3 | TLS_AES_256_GCM_SHA384 | Certificate + Client cert | Internal APIs |
| **CONFIDENTIAL** | TLS 1.3 + mTLS | TLS 1.3 | TLS_AES_256_GCM_SHA384 | Mutual TLS (client + server cert) | Service-to-service communication |
| **RESTRICTED** | TLS 1.3 + mTLS + Pinning | TLS 1.3 | TLS_AES_256_GCM_SHA384 | mTLS + Certificate pinning | Lab integration, payment gateways |

### 2.2 Инструменты идентификации и доступа (IAM)

| Инструмент | Уровень данных | Функция | Реализация |
|---|---|---|---|
| **RBAC (Role-Based Access Control)** | CONFIDENTIAL, RESTRICTED | Ограничение доступа по ролям (Reception, Specialist, Patient, Accountant, Management, Auditor) | Keycloak IAM + Database roles |
| **ABAC (Attribute-Based Access Control)** | RESTRICTED | Доступ на основе атрибутов (например, "Specialist может видеть только пациентов с ID в его списке") | Keycloak + custom application logic |
| **Two-Factor Authentication (2FA)** | CONFIDENTIAL, RESTRICTED (для sensitive roles) | Требование второго фактора при доступе к чувствительным данным | TOTP (Time-based OTP) via Google Authenticator |
| **Multi-Factor Authentication (MFA)** | RESTRICTED (диагнозы, платежи) | MFA для операций высокого риска (изменение диагноза) | Keycloak + SMS OTP |
| **Single Sign-On (SSO)** | INTERNAL, CONFIDENTIAL | Единая аутентификация для всех сервисов | Keycloak OIDC + OAuth 2.0 |
| **API Key Authentication** | SERVICE-TO-SERVICE | Аутентификация между микросервисами | JWT (JSON Web Tokens) signed by Keycloak |

### 2.3 Инструменты целостности данных

| Инструмент | Уровень данных | Функция | Реализация | Алгоритм |
|---|---|---|---|---|
| **HMAC (Hash-based Message Authentication Code)** | CONFIDENTIAL, RESTRICTED | Проверка целостности данных при передаче | TLS + application layer | HMAC-SHA256 |
| **Digital Signature (УКЭП)** | RESTRICTED (диагнозы, контракты) | Юридически значимая подпись врача/пациента | ГОСТ Р 34.10-2012 (Russian standard) | RSA-2048 / ГОСТ |
| **Checksums (CRC32, SHA256)** | INTERNAL, CONFIDENTIAL | Быстрая проверка целостности при хранении | Database stored procedures | SHA-256 |
| **Message Authentication Code (MAC)** | RESTRICTED (платежи) | Проверка целостности платёжных данных | Payment service | HMAC-SHA256 |

| Инструмент | Уровень данных | Примеры | Когда применяется |
|---|---|---|---|
| **PII Masking** | CONFIDENTIAL, RESTRICTED | ФИО: И***в; Телефон: +7-***-**67; Email: a***@mail.ru | Логирование, аналитика, отчёты для аналитиков |
| **Encryption (instead of masking)** | RESTRICTED | Шифрованием сохраняют данные в зашифрованном виде, ключ от Vault | Медицинские данные в БД, платежи в истории |
| **Tokenization** | RESTRICTED (платежи) | 4444-****-****-2222 (реальный номер карты = токен в Vault) | Хранение платёжных реквизитов (PCI DSS compliance) |
| **Pseudonymization** | RESTRICTED (аналитика) | patient_id_XXXXX вместо реального ФИО | Аналитика без привязки к личности |
| **Anonymization (irreversible)** | PUBLIC (от RESTRICTED) | Удаление связи между данными и личностью | Исследования, публичная статистика |
| **Obfuscation in logs** | CONFIDENTIAL, RESTRICTED | patient_id_XXXXX вместо реального ФИО | Логирование операций (security logs) |

### 2.5 Инструменты аудита и логирования

| Инструмент | Уровень данных | Что логируется | Где хранится | Период хранения |
|---|---|---|---|---|
| **Audit Logs (immutable)** | RESTRICTED | ВСЕ операции: кто (user_id), что (action), когда (timestamp), результат (success/failure), data fingerprint | PostgreSQL WORM table + S3 backup | 7 лет (по 152-ФЗ) |
| **Application Logs (ELK Stack)** | CONFIDENTIAL, RESTRICTED | Ошибки, warnings, info, debug | Elasticsearch + Kibana | 90 дней (с аноним. маски) |

| **API Access Logs** | CONFIDENTIAL | API calls, user, timestamp, response code | Kong API Gateway logs | 30 дней |
| **Security Event Logs** | RESTRICTED | Failed logins, unauthorized access attempts, privilege escalation | SIEM (Splunk) | 1 год |
| **Data Access Logs** | RESTRICTED | Who accessed which patient's data, when, what fields | Audit table + SIEM | 7 лет |

## ЧАСТЬ 3: Реализация по компонентам системы

### 3.1 На уровне API Gateway (Kong)

- ✓ Terminates TLS 1.3 (все данные in-transit encrypted)
- ✓ Validates JWT tokens (Keycloak OIDC)
- ✓ Rate limiting (защита от DoS)
- ✓ Request logging (masked PII)
- ✓ Forwards mTLS to backend services

### 3.2 На уровне Application (Microservices)

- ✓ Применение RBAC/ABAC для доступа
- ✓ Маскирование ПИИ в логах и ответах
- ✓ Валидация входных данных (SQL injection prevention)
- ✓ Публикация событий в Message Queue (for audit trail)
- ✓ Вызов Vault для получения encryption keys

### 3.3 На уровне Database (PostgreSQL)

- ✓ Шифрование покоящихся данных (pgcrypto extension)
- ✓ TLS 1.3 для соединения
- ✓ Separate audit table (immutable, WORM)
- ✓ Row-level security policies
- ✓ Резервное копирование в S3 (encrypted)

### 3.4 На уровне Analytics (Data Warehouse)

- ✓ Masking engine преобразует данные перед загрузкой
- ✓ Role-based views (Analyst видит маскированные данные)
- ✓ No sensitive data in BI reports (only aggregated/anonymized)
