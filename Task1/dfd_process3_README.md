# DFD Process 3: Оплата услуг (Payment Processing)

## Обзор процесса

**Название:** Обработка платежа пациента за медицинские услуги  
**Тип:** Финансовый процесс (financial/payment process)  
**Участники:** Пациент → Кассир → ККМ (контрольно-кассовая машина) → 1С:Бухгалтерия  
**Классификация данных:** RESTRICTED (Level 4) — платёжные данные + финансовые записи  
**Критичность:** КРИТИЧНАЯ 
**Частота:** Ежедневно, множество платежей  

---

## ОСНОВНАЯ ПРОБЛЕМА

**Платёжные данные (реквизиты карт) хранятся в открытом виде в Excel и 1С**

```
As-Is:
┌─────────────────────────────────────────────────┐
│ Пациент.xlsx (\\fileserver\Medikamente\)      │
├─────────────────────────────────────────────────┤
│ ФИО        │ Услуга    │ Сумма │ Карта         │
├─────────────────────────────────────────────────┤
│ Иванов И.И.│ Консульт. │ 3000  │ 4111 1111 1111 1111 │
│ Петрова А.В│ УЗИ       │ 2500  │ 4222 2222 2222 2222 │
│ Сидоров П.П│ Анализ    │ 1500  │ 4333 3333 3333 3333 │
└─────────────────────────────────────────────────┘
    ↓
Любой сотрудник может:
├─ Скопировать номера карт
├─ Отправить по email
└─ Взять информацию домой на ноутбуке

РИСК: Утечка реквизитов 1000+ карт пациентов → мошенничество → убытки
```

## Участники (External Entities)

| Участник | Роль | Действия | Данные |
|----------|------|---------|--------|
| ** Пациент** | Плательщик | Предоставляет средства (наличные/карта); может оплатить по-сюду | Реквизиты карты (RESTRICTED) |
| ** Кассир** | Internal actor | Принимает платёж; проводит операцию через ККМ; учитывает в Excel | Полные реквизиты карты |
| ** ККМ** | Electronic device | Обрабатывает карту; отправляет в банк; возвращает результат | Реквизиты карты (временно) |
| ** Банк / Payment Gateway** | External system | Авторизует платёж; снимает деньги; возвращает ответ | Реквизиты карты (protected) |
| ** 1С:Бухгалтерия** | Financial system | Синхронизирует платежи; ведёт учёт; подготавливает отчёты | Реквизиты счёта, суммы (RESTRICTED) |

## Основные процессы (Processes)

### P3.1: Выбор услуги и расчёт стоимости

**Входные данные (Input):**
- Patient_ID (из процесса 1)
- Услуга (из прайс-листа)

**Обработка:**
1. Ресепшен (или автоматизированная система) указывает услугу
2. Система вычисляет стоимость:
   - Базовая цена: 3000 руб.
   - Скидка (если есть): 10% = -300 руб.
   - **Итого: 2700 руб.**

**Выходные данные (Output):**
- Amount: 2700 руб.
- Service: "Консультация кардиолога"
- → передача в P3.2

---

### P3.2: Инициация платежа (сбор реквизитов)

**Входные данные (Input):**
- Amount: 2700 руб.
- Patient: Иванов И.И.

**Обработка:**
1. Кассир запрашивает способ оплаты:
   - "Наличные" → P3.3a
   - "Карта" → P3.3b

2. Если **карта**, кассир:
   - Запрашивает карту пациента
   - Вводит реквизиты в ККМ:
     - Номер карты: 4111 1111 1111 1111
     - Месяц/Год: 05/28
     - CVV: 123
   - **ПРОБЛЕМА:** реквизиты могут быть записаны в систему!

**Выходные данные (Output):**
- Реквизиты платежа (ввод в ККМ)
- → передача в P3.3

---

### P3.3: Обработка платежа через ККМ

**Входные данные (Input):**
- Реквизиты платежа из P3.2
- Amount: 2700 руб.

**Обработка:**
1. ККМ передаёт данные в Payment Gateway (банк)
   - **Как-Is:** без шифрования (TCP plain)
   - **To-Be:** TLS 1.3 (Protected)

2. Банк авторизует платёж:
   - Проверяет баланс: 50000 руб. > 2700 руб. ✓
   - Проверяет 3D Secure (если требуется)
   - Снимает 2700 руб. со счёта
   - Возвращает код авторизации: "AUTH123456"

3. ККМ возвращает результат:
   - Status: "SUCCESS"
   - Transaction ID: "TXN-2026-03-09-001"

**Выходные данные (Output):**
- Payment status: "APPROVED"
- Transaction_ID: "TXN-2026-03-09-001"
- Amount charged: 2700 руб.
- → передача в P3.4

---

### P3.4: Запись в 1С:Бухгалтерия (Accounting)

**Входные данные (Input):**
- Payment status: "APPROVED"
- Amount: 2700 руб.
- Patient: Patient_ID 42

**Обработка:**
1. Кассир вводит платёж в 1С:Бухгалтерия
   - **As-Is:** файловый режим 1С
   - **As-Is:** копирует файл на сетевой диск
   - **As-Is:** нет шифрования при передаче

2. 1С:Бухгалтерия записывает:
   - Дата: 2026-03-09
   - Сумма: 2700 руб.
   - ПИИ пациента: ФИО, адрес, реквизиты счёта
   - Статус: "оплачено"

**Выходные данные (Output):**
- Квитанция (печать или email)
- Запись в D1 (регистр платежей)
- Синхронизация в 1С → D2 (1С:Бухгалтерия)

## Хранилища данных (Data Stores)

### D1: Регистр платежей (Payment Register)

**Текущее состояние (As-Is) — КРИТИЧНОЕ:**
```
Excel файл: Платежи.xlsx
Расположение: \\fileserver\Medikamente\Payments\
Формат:
  | Дата | Пациент | Сумма | Услуга | Карта | Статус |
  |------|---------|-------|--------|-------|--------|
  |2026-03-09| Иванов И.И. | 2700 | Консульт. | 4111111111111111 | оплачено |
  |2026-03-08| Петрова А.В. | 2500 | УЗИ | 4222222222222222 | оплачено |
  |2026-03-08| Сидоров П.П. | 1500 | Анализ | 4333333333333333 | oплачено |

ПРОБЛЕМЫ:
   Номера карт в открытом виде
   Любой сотрудник видит все реквизиты
   Нет шифрования
   Нет RBAC (все видят всех)
   Нет логирования (кто открыл файл?)
   Конфликты версий при синхронизации с 1С
   Риск ransomware (файл может быть зашифрован вредоносом)

PCI DSS VIOLATION! 
```

**Целевое состояние (To-Be) —  ЗАЩИЩЕНО:**
```
PostgreSQL таблица: payments
Структура:
  CREATE TABLE payments (
    id BIGSERIAL PRIMARY KEY,
    patient_id BIGINT NOT NULL REFERENCES patients(id),
    transaction_id VARCHAR(50) UNIQUE NOT NULL,  -- TXN-2026-03-09-001
    
    -- Финансовые данные (низкая чувствительность)
    amount NUMERIC(10, 2) NOT NULL,
    currency VARCHAR(3) DEFAULT 'RUB',
    service_id INT REFERENCES services(id),
    
    -- Платёжные данные - не хранить
    -- Вместо этого используем токен от Payment Gateway:
    payment_method_token VARCHAR(50),  -- от Stripe/Yandex.Kassa
    payment_method_type ENUM ('card', 'bank_transfer', 'cash'),
    card_last_4 CHAR(4),  -- только последние 4 цифры (может быть открыто)
    card_brand VARCHAR(20),  -- Visa, Mastercard
    
    -- Статус платежа
    status ENUM ('pending', 'processing', 'success', 'failed', 'refunded'),
    auth_code VARCHAR(50),  -- от банка
    bank_response_code INT,
    bank_response_message TEXT,
    
    -- Временные метки
    created_at TIMESTAMP DEFAULT NOW(),
    processed_at TIMESTAMP,
    authorized_at TIMESTAMP,
    
    -- Для аудита
    created_by INT REFERENCES users(id),
    
    -- Инкасация (для 1С)
    reconciled_at TIMESTAMP,
    reconciled_by INT
  );
  
  -- Реквизиты хранятся у платёжного сервиса (Stripe/Yandex.Kassa)
```

**Классификация:** RESTRICTED (Level 4)  
**Шифрование:** Платёжные реквизиты НЕ шифруются, так как не хранятся в нашей системе. Вместо этого используется токенизация от платёжного сервиса. 
**Токенизация:**  Обязательна (PCI DSS compliance)  
**Доступ (RBAC):**
- Кассир: create + read own payments
- Бухгалтер: read all (без реквизитов)
- Auditor: read logs only

### D2: 1С:Бухгалтерия (1C Accounting System)

**Текущее состояние (As-Is) — КРИТИЧНОЕ:**
```
Файловый режим 1С
Расположение: \\fileserver\1C\Accounting.db
Синхронизация через копирование файла на диск
 Доступ: все сотрудники видят файл
 Нет шифрования
 Нет RBAC
```

**Целевое состояние (To-Be) —  ЗАЩИЩЕНО:**
```
1С:Бухгалтерия в СЕТЕВОМ режиме (Server-based):
  ├─ 1С РПС (Rich Platform Server)
  ├─ Сетевой режим (not file-based)
  ├─ Запуск на отдельном сервере (Windows Server 2022)
  ├─ Подключение: через VPN + TLS 1.3
  └─ Синхронизация платежей: через API (not file copy)

Интеграция Медикаменте → 1С:Бухгалтерия:
  ├─ Платёж создаётся в PostgreSQL (Медикаменте)
  ├─ Асинхронный процесс отправляет в 1С через API:
  │  POST https://1c.medikamente.local:8080/api/payments
  │    ├─ mTLS (сертификат клиента)
  │    ├─ Body:
  │    │  {
  │    │    "patient_id_token": "<encrypted>",
  │    │    "amount": 2700,
  │    │    "currency": "RUB",
  │    │    "service": "Consultation",
  │    │    "payment_method": "card_token",
  │    │    "timestamp": "2026-03-09T11:00:00Z"
  │    │  }
  │    └─ Signature: HMAC-SHA256
  │
  └─ 1С:Бухгалтерия записывает платёж в его БД
     ├─ Никогда не видит реквизиты карты!
     └─ Видит только: сумма, пациент (ID), услуга, дату
```

## Потоки данных (Data Flows)

### Flow 1: Пациент выбирает услугу и сумму (P3.1)

```
Пациент Иванов И.И.
  │
  ├─ "Хочу оплатить консультацию кардиолога"
  │
  ▼
Кассир (Касса-1)
  │
  ├─ Открывает систему
  ├─ Вводит Patient_ID: 42 (или ФИО)
  ├─ Система показывает услуги:
  │  ├─ Консультация кардиолога: 3000 руб
  │  ├─ УЗИ сердца: 4000 руб
  │  └─ ЭКГ: 500 руб
  │
  ├─ Кассир выбирает: "Консультация кардиолога"
  │
  ▼
Backend System (HTTPS + TLS 1.3):
  │
  ├─ GET /services/id/cardiology-consultation
  │  Response:
  │  {
  │    "id": 1,
  │    "name": "Консультация кардиолога",
  │    "base_price": 3000,
  │    "discounts_applicable": [
  │      { "type": "by_age", "discount_percent": 10 },  -- Пенсионеры
  │      { "type": "loyalty", "discount_percent": 5 }   -- Постоянные пациенты
  │    ]
  │  }
  │
  ├─ Проверка скидок (Patient_ID 42):
  │  ├─ Is senior? FALSE
  │  ├─ Is loyal? TRUE (скидка 5%)
  │  └─ Final discount: 5%
  │
  └─ Calculate final price:
     base_price: 3000
     discount: -150
     final_amount: 2850 руб 
```

---

### Flow 2: Кассир инициирует платёж (P3.2) — КРИТИЧНОЕ!

```
Кассир
  │
  ├─ Запрашивает: "Как оплатить: наличные или карта?"
  ├─ Пациент: "Карта"
  │
  ▼
ВАРИАНТ As-Is (ОПАСНЫЙ):
  │
  ├─ Кассир запрашивает карту
  ├─ Пациент передаёт карту (физический пластик)
  ├─ Кассир ВВОДИТ вручную в ККМ:
  │  ├─ Номер карты: 4111 1111 1111 1111  (открытый текст!)
  │  ├─ Месяц/Год: 05/28
  │  ├─ CVV: 123  (в памяти ККМ!)
  │  └─ Имя: IVAN IVANOV
  │
  ├─ ПРОБЛЕМА: реквизиты могут быть:
  │  ├─ Записаны в логах ККМ
  │  ├─ Переданы в 1С открытым текстом
  │  ├─ Скопированы кассиром в Excel
  │  └─ Украдены вредоносом на ККМ
  │
  └─ PCI DSS VIOLATION! 

ВАРИАНТ To-Be (БЕЗОПАСНЫЙ):
  │
  ├─ Кассир показывает пациенту QR-код
  ├─ Пациент отсканирует QR → открывается защищённая форма
  │  (шифрованная транспортировка: TLS 1.3)
  │
  ├─ Пациент вводит данные карты:
  │  ├─ Форма: HTTPS (зашифрована)
  │  ├─ Зашифрованные поля (input type="password")
  │  └─ Данные НЕ отправляются в нашу систему!
  │
  ├─ Браузер пациента отправляет карту прямо в Payment Gateway
  │  (например, Stripe.js или Yandex.Kassa)
  │
  ├─ Payment Gateway возвращает ТОКЕН:
  │  └─ payment_method_token: "tok_visa_4111" 
  │
  └─ Кассир видит только:
     └─ "Платёж на сумму 2850 руб. Visa ***1111"  (PCI DSS compliant)
```

---

### Flow 3: Кассир отправляет платёж через ККМ (P3.3) — ЗАЩИЩЕНО

```ККМ (кассовая машина)
  │
  ├─ Получает платёжный токен (не полный номер карты!)
  ├─ Отправляет на авторизацию:
  │
  ▼
TLS 1.3 Connection (HTTPS):
  │
  POST https://api.payment-gateway.local/authorize
    ├─ Certificate: signed by Trusted CA
    ├─ Cipher Suite: TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384
    ├─ Body (encrypted in TLS tunnel):
    │  {
    │    "amount": 2850,
    │    "currency": "RUB",
    │    "payment_method": "tok_visa_4111",  ← ТОКЕН, не реальная карта!
    │    "idempotency_key": "uuid-2026-03-09-001"
    │  }
    └─ Signature: HMAC-SHA256(body, shared_secret)
  
  ▼
Payment Gateway (Stripe/Yandex.Kassa):
  │
  ├─ Верифицирует токен
  ├─ Отправляет на авторизацию в банк (по защищённому каналу)
  ├─ Банк авторизует: SUCCESS
  └─ Возвращает результат:
  
  Response (зашифровано):
  {
    "status": "success",
    "transaction_id": "txn_1Ix9QJ...",
    "amount": 2850,
    "card_last_4": "1111",
    "card_brand": "Visa",
    "auth_code": "AUTH123456",
    "timestamp": "2026-03-09T11:00:00Z",
    "signature": "hmac_value"
  }
```

### Flow 4: Платёж сохраняется в БД (P3.4)

```
Backend System
  │
  ├─ Получает ответ от Payment Gateway
  ├─ Проверяет подпись (HMAC)
  │
  ▼
INSERT INTO payments (
  patient_id, transaction_id, amount,
  payment_method_token, payment_method_type,
  card_last_4, card_brand,
  status, auth_code, bank_response_code,
  created_at, created_by
) VALUES (
  42, 'TXN-2026-03-09-001', 2850,
  'tok_visa_4111', 'card',  -- ← ТОКЕН хранится, не реальный номер!
  '1111', 'Visa',
  'success', 'AUTH123456', 0,
  NOW(), 15  -- кассир с ID 15
);

 Результат:
  - Реальный номер карты НЕ сохранён в БД
  - Токен сохранён (используется только для возвратов)
  - Последние 4 цифры видны (для UI)
  - PCI DSS compliant 
```

### Flow 5: Синхронизация с 1С:Бухгалтерия (P3.4 - Reconciliation)

```
Асинхронный процесс (раз в 30 минут):
  │
  ├─ Backend System находит неинкассованные платежи:
  │  SELECT * FROM payments 
  │  WHERE status = 'success' AND reconciled_at IS NULL
  │
  ├─ Для каждого платежа отправляет в 1С:
  │
  ▼
VPN + TLS 1.3:
  │
  POST https://1c.medikamente.local:8080/api/payments/import
    ├─ mTLS: client certificate from HSM
    ├─ Body (encrypted):
    │  {
    │    "patient_id_hash": "hash(patient_id + salt)",  ← НЕ реальный ID!
    │    "amount": 2850,
    │    "service_name": "Cardiology Consultation",
    │    "transaction_id": "TXN-2026-03-09-001",
    │    "payment_date": "2026-03-09",
    │    "payment_method": "card"  ← БЕЗ деталей карты!
    │  }
    └─ Signature: HMAC-SHA256
  
  ▼
 1С:Бухгалтерия получает платёж:
  ├─ Записывает в свою БД
  ├─ Подтверждает:
  │  {
  │    "status": "recorded",
  │    "record_id": "12345",
  │    "timestamp": "2026-03-09T11:30:00Z"
  │  }
  │
  └─ Backend обновляет платёж:
     UPDATE payments SET 
       reconciled_at = NOW(),
       reconciled_by = 1  -- система
     WHERE transaction_id = 'TXN-...';
```
